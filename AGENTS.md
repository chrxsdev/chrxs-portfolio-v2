# Repository Guidelines

## Project Structure & Module Organization
This Vite + React 19 + TypeScript portfolio keeps routes in `src/pages`, shared UI in `src/components`, sections in `src/components/sections`, hooks in `src/hooks`, utilities in `src/lib`, config in `src/config`, and constants in `src/constants`. `src/router.ts` is generated by Generouted; do not edit it. Put public assets in `public/` and bundled assets in `src/assets`.

## Build, Test, and Development Commands
Use `pnpm` because the repo ships with `pnpm-lock.yaml`.

- `pnpm dev` starts the local Vite dev server.
- `pnpm build` runs `tsc -b` and produces a production build.
- `pnpm lint` runs ESLint across the project.
- `pnpm preview` serves the built app locally for a final smoke test.

## Coding Style & Naming Conventions
Write TypeScript/TSX with 2-space indentation, single quotes, and semicolons. Use `PascalCase` components, `camelCase` hooks/utilities, and folder-based routes. Define prop interfaces, use `import type`, avoid `any`, and prefer `@/components`, `@/lib`, and `@/hooks`. ESLint uses `typescript-eslint`, `react-hooks`, and `react-refresh`.

## Refactor Guardrails
Preserve the font, palette, Tailwind tokens, and Supabase backend. Improve layout, hierarchy, spacing, and accessible motion instead of rebranding. Use `cn()` for conditional classes, mobile-first semantic HTML, meaningful alt text, and async loading/error states. Check `package.json` before adding a dependency.

## Testing Guidelines
There is no automated test runner configured yet, and no coverage gate is enforced. Until one is added, every change should pass `pnpm lint` and `pnpm build`, plus a manual browser check for affected routes. If you introduce tests, use `*.test.ts` or `*.test.tsx` and keep them close to the feature they verify.

## Commit & Pull Request Guidelines
Recent history mixes short subjects like `updating music title` with Conventional Commit-style entries like `feat: add Supabase icon support...`. Prefer concise, imperative commit messages under 72 characters; `feat:`, `fix:`, and `refactor:` are welcome when useful. PRs should include a clear summary, screenshots or recordings for visual changes, notes about any env/config updates, and confirmation that `pnpm lint` and `pnpm build` passed.

## Security & Configuration Tips
Required environment variables are validated in `src/config/env.ts`: `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`. Keep secrets in `.env`, never commit credentials, and call out any new public env vars in the PR description.
